一张卡片放在正文里是两栏布局，放进三百像素宽的侧栏就该变成一栏。用媒体查询做这件事会很难受：视口宽度没变，是「它所在的容器」变了。

容器查询把判断依据从视口换成了容器本身。

## 声明容器

先给父元素一个容器名字，再针对它写条件：

```css
.card-list {
  container-type: inline-size;
  container-name: cards;
}

@container cards (min-width: 30rem) {
  .card {
    display: grid;
    grid-template-columns: 96px minmax(0, 1fr);
    gap: 1.25rem;
  }
}
```

`inline-size` 表示只按行内方向的尺寸（通常就是宽度）来触发，这也是最常见、性能最好的一种。

## 与媒体查询的分工

| | 媒体查询 `@media` | 容器查询 `@container` |
| --- | --- | --- |
| 判断依据 | 视口宽度 | 最近的容器尺寸 |
| 适合 | 页面级布局：导航折叠、页宽 | 组件级布局：卡片、列表项 |
| 复用 | 换个位置就要重写一遍 | 跟组件一起走 |
| 代价 | 无 | 父级要显式声明容器 |

判据很简单：**如果换一个位置排版就该变，用容器查询；如果整页都该变，用媒体查询。**

## 三个容易忘的细节

- 容器查询不能跨组件「穿透」，它只看最近的已命名祖先。
- `container-type: inline-size` 会让该元素的尺寸不再受内容撑开影响，包裹长文本时要确认没有副作用。
- 不支持容器查询的浏览器会直接忽略整块规则，所以基础样式必须先写在容器查询之外。

> [!TIP]
> 先用媒体查询写出能看的样子，再把它挪进容器查询。顺序反了容易把「组件该长什么样」和「页面该长什么样」混在一起想。
